# 一期状态机说明

所有状态转换由后端命令执行，并同时写状态历史和审计事件。前端提交“动作”，不得提交任意目标状态。

## 1. 供应商申请

`DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED`

分支：`UNDER_REVIEW → RETURNED → SUBMITTED`；`UNDER_REVIEW → REJECTED`；`DRAFT/RETURNED → WITHDRAWN`。

## 2. 数据集主状态

`DRAFT → SUBMITTED → ADMISSION_CHECKING → ADMISSION_PASSED → REGISTRATION_REVIEW → REGISTERED → QUALITY_CHECKING → QUALITY_PASSED → LISTING_REVIEW → LISTED`

分支：

- `ADMISSION_CHECKING → MANUAL_REVIEW → ADMISSION_PASSED | REMEDIATION_REQUIRED | ADMISSION_REJECTED`
- `REMEDIATION_REQUIRED → ADMISSION_CHECKING`
- `REGISTRATION_REVIEW → REGISTRATION_RETURNED → REGISTRATION_REVIEW`
- `QUALITY_CHECKING → QUALITY_REVIEW → QUALITY_PASSED | QUALITY_REMEDIATION_REQUIRED`
- `QUALITY_REMEDIATION_REQUIRED → QUALITY_CHECKING`（绑定新任务/适用的新版本）
- `LISTING_REVIEW → LISTING_RETURNED → LISTING_REVIEW`
- `LISTED → PAUSED → LISTED | DELISTED`
- `LISTED → DELISTED`

硬约束：准入未通过不得登记；登记未通过不得测评；质量门槛未通过不得上架；暂停/下架不得产生新订单。

## 3. 质量任务

`CREATED → ACCEPTED → RUNNING → REVIEW_PENDING → PASSED | FAILED`

异常：`RUNNING → EXECUTION_FAILED → RUNNING`（重试）；`FAILED → REMEDIATION_OPEN → RETEST_CREATED`。取消只允许 `CREATED/ACCEPTED → CANCELLED`，且必须记录原因。

## 4. 订单

`DRAFT → SUPPLIER_CONFIRMATION → CONTRACT_CONFIRMATION → AUTHORIZATION_PENDING → DELIVERY_PENDING → DELIVERING → DEMANDER_CONFIRMATION → COMPLETED → ARCHIVED`

异常与终止：

- `SUPPLIER_CONFIRMATION → RETURNED → DRAFT`
- `SUPPLIER_CONFIRMATION → REJECTED`
- `DRAFT/SUPPLIER_CONFIRMATION → CANCELLED`
- `DELIVERY_PENDING/DELIVERING/DEMANDER_CONFIRMATION → DELIVERY_EXCEPTION`
- `DELIVERY_EXCEPTION → REDELIVERY → DELIVERING`
- 有权运营人员可从非终态进入 `TERMINATED`，必须给出原因。

硬约束：合同双方未确认不得授权；授权未激活不得交付；未确认或异常未关闭不得完成；完成订单不可回退，只能追加纠错/归档记录。

## 5. 合同、授权、交付

- 合同：`DRAFT → UPLOADED → SUPPLIER_CONFIRMED → BOTH_CONFIRMED → EFFECTIVE → EXPIRED | TERMINATED`。若需求方先确认，使用对称的 `DEMANDER_CONFIRMED`。
- 授权：`PENDING → ACTIVE → EXHAUSTED | EXPIRED | REVOKED`。
- 交付：`CREATED → PREPARING → READY → DOWNLOADING → DELIVERED → CONFIRMED`；异常为 `PREPARING/READY/DOWNLOADING/DELIVERED → EXCEPTION → REDELIVERY | CLOSED`。

## 6. 并发规则

所有命令携带资源版本或 `If-Match`。数据库以乐观锁拒绝过期写入；下载次数使用条件更新 `used < limit`，同一下载票据只能成功消费一次。
