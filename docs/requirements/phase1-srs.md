# 高质量数据集管理运营平台一期需求规格说明书

- 文档状态：评审稿 v0.1
- 基线日期：2026-09-02
- 依据：用户一期建设要求、《高质量数据集建设》、内网中间件部署清单

## 1. 建设目标与范围

一期交付唯一目标是形成可真实运行、可持久化、可追踪、可异常处理、可审计的最小业务闭环：

供应商入驻 → 数据集接入 → 准入检测 → 数据集登记 → 质量测评 → 整改复测 → 上架审核 → 数据集市场 → 用户订购 → 合同记录 → 使用授权 → 受控交付 → 交付确认 → 业务归档。

核心状态只能由后端命令和状态机变更。不得以静态页面、模拟接口、浏览器本地状态或人工改库代替核心能力。

### 1.1 一期角色

- 平台管理员：系统、角色、基础配置和审计管理。
- 平台运营人员：供应商、登记、上架、订单和交付异常处理。
- 数据集供应商：入驻、接入、登记、整改、上架、订单确认和交付协同。
- 数据需求方：市场检索、订购、合同确认、下载和交付确认。
- 质量测评人员：任务受理、测评执行、报告确认。
- 人工复核人员：接入风险、问题样本和质量结果复核。

### 1.2 明确不在一期

模型市场/训推、第三方服务机构市场、需求大厅、支付退款发票分账、CA/电子印章、区块链、EDC 跨域连接器、自然语言合约策略、可视化算子编排、全模态深度 AI、复杂图谱/推荐、多级复杂租户及下载后防复制打印均不实现。Cleanlab 只允许一个有标签数据集试点；FiftyOne 仅在试点确有影像且单独确认后接入。

## 2. 业务术语

- 数据集：业务上的数据产品主体，具有永久唯一标识。
- 数据集版本：不可变的数据文件、清单、元数据及质量结果集合。
- 接入批次：一次上传或资源引用形成的技术接收记录。
- 准入检测：登记前的完整性、可读性、格式、恶意文件接口、基础敏感信息和申报一致性检查。
- 登记申请：供应商将已通过准入的数据集版本登记为平台产品的申请。
- 质量任务：针对一个不可变数据集版本和一版测评标准的测评执行记录。
- 上架：将已登记且达到质量门槛的数据集版本发布到市场。
- 订单：需求方对指定数据集版本、用途和期限的订购意向及履约主记录。
- 授权：合同确认后生成的主体、版本、有效期和次数约束。
- 交付：平台托管文件在授权约束下的受控下载任务及确认结果。

## 3. 功能需求

### 3.1 身份与供应商

- **IAM-001**：系统必须通过 OIDC 登录、退出并读取当前用户基础信息与角色；禁用用户的访问令牌在可接受窗口内失效。
- **IAM-002**：菜单、接口和数据范围必须同时校验，不得仅依赖前端隐藏。
- **SUP-001**：用户可创建供应商入驻草稿，填写主体信息并上传资质材料。
- **SUP-002**：提交后必须生成不可变申请编号、提交快照和 Flowable 流程实例。
- **SUP-003**：运营人员可通过、退回补充或拒绝；处理意见、处理人和时间必须留存。
- **SUP-004**：通过后授予供应商角色并建立供应商与用户的归属关系；拒绝不得授予权限。
- **SUP-005**：供应商可查询当前状态、历史意见和材料版本。

### 3.2 数据集接入

- **DATA-001**：已认证供应商可创建数据集草稿，维护名称、癌种、模态、数据类型、来源、用途和应用场景。
- **ING-001**：系统支持 CSV、JSON、Excel、文本、图片和压缩包的文件上传；每次形成独立接入批次。
- **ING-002**：文件先进入 MinIO 受控接收区，与正式区、样例区和交付区隔离。
- **ING-003**：文件清单必须记录相对路径、媒体类型、字节数、SHA-256、上传状态和 Dataverse 文件引用。
- **ING-004**：系统必须识别扩展名与文件魔数，完成基础解析并逐文件记录失败原因；压缩包需防路径穿越、压缩炸弹和嵌套深度超限。
- **ING-005**：上传会话支持分片、断点续传、重试、幂等完成和超时清理；业务最终状态保存在数据库。
- **ING-006**：接入完成后在 Dataverse 创建或关联草稿数据集版本，保存平台产品 ID、Dataverse Dataset ID 和版本映射。

### 3.3 准入检测与整改

- **COMP-001**：系统真实执行文件存在性、可读性、格式合法性、哈希完整性、申报一致性和基础敏感信息检查。
- **COMP-002**：恶意文件检测必须有真实适配接口；在内网扫描引擎未就绪时任务应明确标记“阻塞/未执行”，不得伪造通过。
- **COMP-003**：Presidio 结果只形成风险提示，输出类型、位置、置信度和严重等级，不替代人工合规结论。
- **COMP-004**：自动结论只允许 `PASS`、`SUSPECTED`、`FAIL`；疑似或策略要求的高风险项生成 Flowable 人工复核任务。
- **COMP-005**：自动结果、人工意见和最终结论必须分别保存，禁止覆盖。
- **COMP-006**：退回整改后必须创建新检测运行，保留前后问题与材料关联。
- **COMP-007**：只有最终结论通过的数据集版本才能提交登记。

### 3.4 登记与版本

- **REG-001**：供应商可从通过准入的版本创建登记草稿并提交审核。
- **REG-002**：提交时固定数据集版本、文件清单、检测结果和元数据快照。
- **REG-003**：运营人员可通过、退回或拒绝登记；退回可补充再提交，供应商可在受理前撤回。
- **REG-004**：审核通过后生成全局唯一数据集标识和初始已登记版本。
- **VER-001**：一期支持一次版本更新；任何数据实体或实质元数据变化都形成新版本，不覆盖当前版本。
- **VER-002**：新版本必须重新执行适用的准入、质量和上架审核，旧版本在新版本生效前保持有效。
- **VER-003**：版本历史必须展示形成、生效、失效、文件哈希、检测、质量和发布关系。

### 3.5 质量测评

- **QUAL-001**：系统对已登记的不可变数据集版本创建质量任务，固定测评标准版本。
- **QUAL-002**：Data-Juicer 适配器必须真实启动检测流水线，支持只检测、不删除、不修改正式数据。
- **QUAL-003**：任务进度、算子状态、指标结果和问题样本必须持久化；执行失败可安全重试且不重复汇总。
- **QUAL-004**：一期覆盖完整性、唯一性、规范性、一致性、可用性、标注质量、隐私残留、数据分布与代表性。
- **QUAL-005**：预置结构化癌症数据、医学文本、医学影像基础三套固定标准；不提供可视化编排。
- **QUAL-006**：疑似问题样本可进入人工抽样复核，自动值、人工值和采用值分别留存。
- **QUAL-007**：系统按固定规则计算维度得分、综合得分、等级和门槛结论，并生成结构化质量报告。
- **QUAL-008**：不合格任务生成整改清单；供应商提交反馈后对新版本/新批次复测，原报告不可覆盖。
- **QUAL-009**：报告与具体数据集版本、测评标准版本、执行器版本和规则版本绑定，并回写 OpenMetadata 索引。

### 3.6 上架与市场

- **LIST-001**：只有登记通过、质量门槛通过且无未关闭高风险项的版本才能申请上架。
- **LIST-002**：上架申请维护使用条件、授权期限范围、交付方式和价格说明；一期不计算或收取在线支付。
- **LIST-003**：运营人员可通过或退回上架；通过后同步 Dataverse 发布状态和 OpenMetadata 展示索引，失败进入可重试同步任务。
- **LIST-004**：已上架数据集可暂停、恢复或申请下架；历史订单的有效授权按合同继续，除非被终止。
- **MARKET-001**：匿名/登录用户按权限查看已上架数据集列表和详情；下架、暂停或无权数据不得作为可订购项。
- **MARKET-002**：支持关键词、癌种、模态、供应商和质量等级筛选。
- **MARKET-003**：详情展示元数据、脱敏样例、质量摘要、版本、使用条件和订购入口，不暴露原生 Dataverse/OpenMetadata 后台。

### 3.7 订单、合同、授权和交付

- **ORDER-001**：需求方对已上架的指定数据集版本提交订单，填写用途、期限和使用主体。
- **ORDER-002**：供应商可确认、退回修改或拒绝；所有动作通过状态机校验。
- **ORDER-003**：需求方可在供应商确认前取消；之后取消需运营处理并记录原因。
- **CONTRACT-001**：供应商或运营人员上传线下合同文件，记录合同号、版本、双方、有效期、SHA-256 和订单关联。
- **CONTRACT-002**：供需双方分别确认同一合同文件哈希后合同状态才可变为已确认；一期不做 CA、电子签章或法律效力推断。
- **AUTH-001**：合同确认后生成对指定主体、数据集版本、有效期、下载次数的授权；授权范围不可宽于合同。
- **AUTH-002**：授权可到期、撤销或耗尽；每次下载原子扣减次数并记录审计。
- **DELIVERY-001**：一期仅支持平台托管文件交付；根据授权创建交付任务和限时、单主体绑定的下载票据。
- **DELIVERY-002**：下载接口必须再次校验用户、授权、有效期、剩余次数、任务状态和对象归属，不能把 MinIO 永久地址暴露给客户端。
- **DELIVERY-003**：下载日志记录文件、时间、主体、结果、字节数、请求 ID 和哈希校验结果；敏感令牌不得写日志。
- **DELIVERY-004**：需求方可确认交付或提出版本不符、缺失、不可访问、校验失败等异常。
- **DELIVERY-005**：异常支持重新交付、补充交付或人工关闭；异常未关闭不得将订单完成。
- **ARCHIVE-001**：交付确认后订单转完成并形成业务归档快照，保留供应商、版本、合同、授权、交付和审计引用。

### 3.8 运营、通知与审计

- **OPS-001**：运营后台提供统一待办，聚合 Flowable 人工任务但按业务权限二次过滤。
- **OPS-002**：支持供应商审核、接入复核、登记审核、质量复核、上架审核、订单查询和交付异常处理。
- **NOTIFY-001**：关键状态变化产生站内信；邮件/短信只作为可选通道，发送失败不回滚业务事务。
- **AUDIT-001**：所有状态变更必须记录对象、前后状态、操作者、原因、请求 ID、时间和业务版本号。
- **AUDIT-002**：查看受限样本、合同下载、交付下载、权限变更均记录安全审计。
- **AUDIT-003**：审计记录仅追加，业务接口不得修改或删除。

## 4. 异常与一致性要求

- **ERR-001**：外部系统超时不得产生未知业务终态；使用 `PENDING_SYNC`/重试任务表达待同步。
- **ERR-002**：重复提交使用 `Idempotency-Key`，返回首个成功结果；冲突返回 409。
- **ERR-003**：状态更新使用乐观锁；过期版本写入返回 409 并返回当前状态。
- **ERR-004**：Kafka 事件采用 Outbox；消费者幂等，重试耗尽进入死信并产生运营告警。
- **ERR-005**：Dataverse/OpenMetadata/质量服务的引用必须可对账；对账任务只修复映射或重放事件，不直接改对方数据库。

## 5. 非功能要求

- **NFR-001 性能**：常规查询 P95 ≤ 2 秒，状态命令 P95 ≤ 3 秒（不含异步检测/上传）；100 并发用户下错误率 < 1%。
- **NFR-002 上传**：单文件目标支持 10 GB，分片可恢复；实际内网带宽与网关限制由 PoC 校准。
- **NFR-003 安全**：OIDC、最小权限、对象级授权、上传隔离、文件类型验证、签名 URL 短时有效、凭据不入库。
- **NFR-004 可用性**：核心服务健康检查、结构化日志、指标、链路请求 ID、外部依赖超时/重试/熔断。
- **NFR-005 备份**：业务库每日全量并具备 WAL/PITR；对象和配置按既有设施策略备份，恢复演练纳入验收。
- **NFR-006 审计**：业务和下载审计至少保留三年，具体期限在安全制度评审时确认；日志中敏感字段脱敏。
- **NFR-007 可维护性**：数据库迁移可重复执行；API、事件和状态机有契约测试；关键模块单元覆盖率目标 80%。
- **NFR-008 源码可控**：OpenMetadata、Dataverse、Data-Juicer、Presidio 必须先进入项目自有 Fork，再以固定提交的 Git Submodule 纳入 `Code/opensource`；所有定制提交到自有 Fork并记录上游版本、修改、许可证、构建与升级策略。Flowable 一期优先采用 Maven 依赖和扩展接口，确认必须修改内核后才纳入完整源码。

## 6. 一期验收

验收数据必须是真实测试文件，OpenMetadata、Dataverse、Data-Juicer、Presidio、Flowable 必须在测试证据中出现真实调用记录。端到端测试覆盖用户给定的 20 项验收标准，并额外验证：非法状态跳转被拒绝、重复请求幂等、外部服务失败可恢复、越权访问被拒绝、下载票据过期/耗尽不可用、审计链可按业务 ID 还原。

## 7. 二期边界

一期仅预留模型市场、EDC、MLflow、Kubeflow、KServe 和复杂策略执行的适配接口或领域事件名称，不创建空工程、不部署组件、不实现页面。二期工作必须等待一期验收与用户确认。
